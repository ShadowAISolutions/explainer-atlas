Bit 6 is broken. Two of the three circles have gone red, and they overlap on exactly one region, which holds bit 6. Nothing told the decoder where to look. It ran three parity checks, wrote down which ones failed as a three-digit binary number, and that number was the answer.

Why the checks land on the position

Number the seven slots 1 to 7 and write each number in binary. Check A covers every position whose binary form has the ones digit set, which is 1, 3, 5 and 7. Check B covers the twos digit: 2, 3, 6, 7. Check C covers the fours digit: 4, 5, 6, 7. Every position is in a different combination of checks, because every number from 1 to 7 has a different binary form. That is the whole trick.

failed checks C B A bit 6 broken 1 1 0 = 6 bit 3 broken 0 1 1 = 3 nothing broken 0 0 0 = no error

Positions 1, 2 and 4 belong to one check each, so each is used as that check's parity bit, set to whatever makes its circle even. The other four positions carry the message. Flip a message bit and several circles go red; flip a parity bit and exactly one does. Either way the red ones name the position, so the code repairs its own repair machinery as readily as the message.

Sixteen spheres that fill the space exactly

There are 2⁷ = 128 possible seven-bit words and only 16 of them are valid. Around each valid word sit the seven words one flip away, giving 16 × 8 = 128. The spheres do not overlap and they leave nothing out; every one of the 128 words is either a codeword or one flip from exactly one codeword. A code that fills the space with no slack is called perfect, and there are very few of them.

The exactness has a cost. With nothing left over there is no room to say “this word is suspicious”. Tick two flips and watch: the syndrome is never zero, so the decoder is sure it has found a single error, and it confidently flips a third bit. Three bits then differ from what you sent, every time. Adding the eighth bit buys the slack back — with the overall count also checked, a double error keeps the overall parity even while the syndrome stays nonzero, and that contradiction is the decoder saying it cannot fix this one.

What it buys

Seven bits carry four, a rate of 4/7. At a one percent error rate, four raw bits arrive intact about 96.1% of the time; the same four inside a codeword arrive intact 99.8% of the time, a twentyfold cut in failures for three extra bits. Simply sending everything three times and voting does slightly better still, but it costs twelve bits instead of seven. Push the slider to 0.5 and the two lines meet exactly at 15/16, which is the same 1 + 7 = 8 turning up again: when every bit is a coin toss the code has nothing to work with.

What to try

Flip bit 1, the parity bit for check A. Only one circle reddens and the syndrome reads 1. Now flip bits 3 and 5 together and read the decoded row: the syndrome says 6, the decoder flips bit 6, and the word now differs from yours in three places. Switch the eighth bit on, leave both flips in place, and the verdict changes from a confident repair to a refusal.
