If every symbol costs the same number of bits, you are paying for E exactly what you pay for A, however rare it is. The fix is obvious in outline — short codes for common symbols — and immediately runs into a problem. If A is 0 and B is 01, then the stream 01 is ambiguous. Variable-length codes only work if no codeword is a prefix of another.

That constraint is exactly what a binary tree enforces. Put every symbol at a leaf, read left branches as 0 and right as 1, and a codeword is the path to its leaf. No leaf lies on the path to another leaf, so no codeword prefixes another — for free, by construction.

The greedy step

So the question becomes which tree. Huffman's answer, from a 1952 term paper set by Robert Fano, is to build it from the bottom. Treat every symbol as a one-node tree. Take the two lowest-weight trees, join them under a new node whose weight is their sum, and put it back. Repeat until one tree remains.

Step the merge slider from zero and watch. The two rarest symbols pair up first, which pushes both one level deeper — so they end up with the longest codes. Every subsequent merge adds one bit to everything underneath it. Since the rarest symbols get buried earliest, they accumulate the most bits, and the most common symbol, joined last, sits one branch from the root.

The argument that this is optimal has two halves. First, in some optimal tree the two least frequent symbols are siblings at maximum depth — if they were not, you could swap them with whatever is down there and the total would not increase. Second, merging them into one composite symbol leaves a smaller problem whose optimal solution extends to an optimal solution of the original. Induct, and greedy is exactly right.

How close to the bound

The floor is the entropy of the source:

H = −Σ pᵢ log₂ pᵢ

and no uniquely decodable code can average fewer bits per symbol than that. Huffman coding always lands in a narrow band above it:

H ≤ L < H + 1

Set the counts to 32, 16, 8, 8 and 1 — near powers of two — and the gap nearly closes. Now set every symbol equal at 20. The entropy of five equally likely symbols is log₂5 ≈ 2.322 bits, but codewords come in whole bits, so Huffman produces lengths of 2, 2, 2, 3, 3 and averages 2.4. That 0.078-bit overhead is not a flaw in the algorithm; it is the cost of insisting each symbol gets a whole number of bits. Arithmetic coding gives that up and gets closer to H.

What to try

Drag E from 2 up to 60. The tree restructures partway up, and A's code gets longer while E's shrinks — the code is a function of the distribution alone, which is why a real compressor must either transmit the tree or agree on one in advance.

Then make the distribution as lopsided as the sliders allow: one symbol at 60, the rest at 1. L drops towards 1.3 bits while the fixed-length code still needs 3. That ratio is the entire business model of compression.
