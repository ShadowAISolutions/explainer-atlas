The pattern in the box is six characters long. Set the length slider to fourteen and read the first number under the stage. A backtracking engine needs sixty-five thousand steps to decide that fourteen letter as are not matched by (a+)+b. The automaton needs fifteen. Push the slider to sixteen and the first number quadruples while the second goes up by two.

Where the work comes from

A backtracking engine is a depth-first search. To match (a+)+ against a run of as it must decide how many as the inner + eats on each pass of the outer +. Every way of cutting the run into consecutive non-empty pieces is a distinct candidate. Cutting k letters is choosing which of the k−1 gaps to cut, so there are 2^(k−1) ways; and because the outer + may also stop short of the end, the engine tries this for every prefix length from one to n:

attempts at the final b = 1 + 2 + 4 + ... + 2^(n-1) = 2^n - 1 n = 10 -> 1023 n = 20 -> 1048575 n = 40 -> about 1.1e12

Every one of them fails, and only then does the engine back up and try the next. The pattern never mentions exponentials; the search order supplies them. The page counts those attempts with the engine, counts them again with a recurrence that knows nothing about regular expressions, and demands the two agree exactly — which is the evidence that the blow-up is combinatorial rather than a bug.

Why the automaton is immune

The other engine never chooses. It numbers the literal positions in the pattern, works out which positions can follow which, and then tracks the set of positions that are still live. Reading a character moves the whole set forward at once. There are only as many positions as there are literals, so the set has a bounded number of members and each character costs a bounded amount of work. Total cost: one step per character, plus one to start. That is the flat line in the chart, and it does not care how ambiguous the pattern is, because ambiguity is exactly what a set absorbs.

Both engines accept precisely the same strings. The page checks this by running every string over the alphabet up to six characters long through both, for every example pattern, and demanding they agree on all of them. Same language, same answers, wildly different bills.

What to try

Load a+b. The two curves lie on top of each other: an unambiguous pattern gives the backtracking engine nothing to choose, so it does linear work too. Now load (a|a)*b, where the branches of the alternation are identical and every one of them has to be tried. Then load (a|aa)*b, whose branches are merely of unequal length. The curve is still a straight line on the log scale, but a shallower one: the splits are now the ways to tile a run with pieces of size one and two, which is a Fibonacci number, so the work grows by a factor of 1.618 per character instead of 2. A gentler catastrophe is still a catastrophe.

Then change the test string to aaaab, which the pattern does match, and watch the lower panel. Greedy matching guesses right on the first pass, so the successful case costs one attempt at the final b and linear work overall. The disaster appears only when the match fails. That is why catastrophic patterns survive testing and die in production, where the failing input is the one somebody chose.
