A Guess About Distance Is Worth Half the Search

Dijkstra's algorithm finds the shortest path without knowing which way the goal is. Tell it roughly which way, and it stops digging in the wrong directions — while still returning exactly the same path, provided the guess never lies upward.

Both algorithms on this page do the same thing: repeatedly take the most promising unexpanded cell, mark it done, and offer its neighbours to the queue. They differ in one number — how they rank what counts as promising.

Dijkstra ranks by g, the confirmed distance from the start. It expands cells in rings, nearest first, in every direction at once. It has no idea where the goal is, so it cannot prefer one direction over another. Set the distance guess to none and step forward: the shaded region grows as a diamond, spreading backwards past the start as eagerly as forwards.

A* ranks by g + h, where h is a guess at the distance still to go. The guess costs nothing to compute — on a grid it is just the difference in coordinates — and it tilts the queue toward the goal. Switch to Manhattan on the same maze and step forward again. The shaded region is now a wedge pointing at the corner. The path that comes out is the same length.

What admissible means and why it is enough

The guess is called admissible when it never overestimates:

h(n) ≤ true remaining cost from n, for every n

On a four-connected grid where every move costs 1, the Manhattan distance is exactly the number of moves needed with no walls at all. Walls can only make the real journey longer, never shorter, so Manhattan can never overshoot. The straight-line distance is smaller still, so it is admissible too — and being a weaker guess, it prunes less.

Admissibility is what buys correctness. When A* pops the goal, any cell still on the queue has g + h no larger than the goal's cost, and since h understates the remainder, no route through it can be shorter. There is nothing left that could beat the answer, so the search can stop. Dijkstra is exactly this argument with h = 0, which is admissible by default and also useless as a hint.

The cost of overconfidence

Choose Manhattan × 2.5. The search narrows to a thin corridor and finishes in a fraction of the expansions — genuinely faster, sometimes by a factor of five. Now check the path length against Dijkstra's. On some mazes it matches. On others it is longer.

That is the whole trade. An inflated guess makes the search so keen to move goalwards that it commits to a detour before discovering the shorter way around a wall, and stops before it can be talked out of it. Nothing warns you: it returns a valid path, just not the shortest. Step through maze 15 with the overconfident guess: the shortest route is 52 steps and it hands back 66. Maze 28 turns 40 into 52. It walks straight past the opening it should have taken, and never looks back.

What to try

Pick any maze and read the bar chart at the bottom. Dijkstra's bar is always the tallest and the overconfident one always the shortest, with the two honest guesses in between — Manhattan beating the straight line every time, because on this grid it is the tighter bound while still never lying. Then run each to completion and compare path lengths: the first three always agree, and only the fourth ever differs.
